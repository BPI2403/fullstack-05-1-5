# О сервисе

«Финансист» — приложение для личного финансового учёта.

- Пользователь записывает доходы и расходы.
- Пользователь задаёт категории и месячные лимиты расходов.
- Приложение показывает баланс, прогресс бюджетов и отчёты.
- Пользователь экспортирует отчёты в форматах CSV и PDF.
- Данные каждого пользователя хранятся в PostgreSQL. Доступ — по учётной записи.
- Клиент — Next.js и React. Сервер — FastAPI. База данных — PostgreSQL.

# Термины

| Термин | Значение |
| --- | --- |
| Операция | Запись о доходе или расходе. Содержит сумму, дату, категорию и описание. |
| Категория | Группа операций. Категория имеет тип: доход или расход. |
| Бюджет | Месячный лимит расходов для одной категории. |
| Отчёт | Сводка операций за период. Включает диаграмму, итоги и файл экспорта. |
| Пользователь | Владелец своих операций, категорий и бюджетов. |
| Access token | Короткоживущий JWT. Даёт доступ к защищённым маршрутам API. |
| Refresh token | Долгоживущий токен. Обновляет access token. Хранится в БД в виде хеша. |

# Экраны

| Экран | Адрес | Содержимое |

# Пользовательские сценарии

## Зарегистрироваться

1. Откройте экран «Регистрация».
2. Введите email.
3. Введите пароль. Минимум 8 символов.
4. Введите имя. Поле необязательное.
5. Нажмите кнопку «Зарегистрироваться».

Результат: приложение создаёт учётную запись и открывает главный экран. Email должен быть уникальным.

## Войти

1. Откройте экран «Вход».
2. Введите email и пароль.
3. Нажмите кнопку «Войти».

Результат: приложение открывает главный экран. Неверный email или пароль даёт сообщение «Неверный email или пароль».

## Выйти

1. Нажмите кнопку «Выйти» в нижней части боковой панели.

Результат: приложение очищает токены и открывает экран входа. Refresh token сессии отозван в БД. Обновление access token по нему больше невозможно.

## Добавить операцию

1. Откройте экран «Транзакции».
2. Нажмите кнопку «Добавить операцию».
3. Выберите тип операции: доход или расход.
4. Введите сумму.
5. Выберите категорию и дату.
6. Введите описание. Поле необязательное.
7. Нажмите кнопку «Добавить».

Результат: операция появляется в начале списка.

## Изменить операцию

1. Откройте экран «Транзакции».
2. Найдите операцию в списке.
3. Нажмите кнопку с тремя точками в строке операции.
4. Выберите пункт «Изменить».
5. Измените данные в форме.
6. Нажмите кнопку «Сохранить».

Результат: список показывает новые данные.

## Удалить операцию

1. Откройте экран «Транзакции».
2. Найдите операцию в списке.
3. Нажмите кнопку с тремя точками в строке операции.
4. Выберите пункт «Удалить».
5. Подтвердите удаление.

Результат: приложение удаляет операцию из списка.

## Добавить категорию

1. Откройте экран «Категории».
2. Нажмите кнопку «Добавить категорию».
3. Введите название. Название должно быть уникальным.
4. Выберите тип: доход или расход.
5. Выберите иконку.
6. Нажмите кнопку «Добавить».

Результат: категория появляется в списке своего типа.

Изменение и удаление категории повторяют шаги сценариев «Изменить операцию» и «Удалить операцию». Работайте на экране «Категории».

## Добавить бюджет

1. Откройте экран «Бюджеты».
2. Нажмите кнопку «Добавить бюджет».
3. Выберите категорию расходов.
4. Введите лимит.
5. Нажмите кнопку «Добавить».

Результат: на экране появляется карточка бюджета.

Карточка показывает потраченную сумму, лимит, остаток и процент. Цвет шкалы меняется. Жёлтый цвет — расход от 90 %. Красный цвет — лимит превышен.

## Экспортировать отчёт

1. Откройте экран «Отчёты».
2. Выберите период: месяц, квартал или год.
3. Выберите формат: CSV или PDF.
4. Нажмите кнопку «Скачать».

Результат:

- Формат CSV — браузер сохраняет файл. Файл содержит метку BOM. Кириллица открывается в Excel без ошибок.
- Формат PDF — приложение открывает окно печати. Выберите «Сохранить как PDF».

# Правила ввода данных

Формы проверяют данные до отправки. Ошибка блокирует отправку.

- Сумма и лимит: обязательные поля. Значение больше нуля. Не больше двух знаков после запятой.
- Категория: обязательное поле.
- Дата: обязательное поле. Дата не может быть в будущем.
- Название категории: от 2 до 30 символов. Название уникально.
- Описание: не больше 200 символов.

При ошибке приложение показывает текст под полем. Поле получает красную рамку. Форма кратко встряхивается.

# Состояния данных

Каждый экран показывает одно из трёх состояний.

- **Загрузка.** Приложение показывает скелетоны вместо данных.
- **Ошибка.** Приложение показывает сообщение и кнопку «Повторить». Кнопка запускает загрузку снова. Ошибка появляется при недоступности сервера.
- **Нет данных.** Приложение показывает заглушку с подсказкой.

Ошибки форм сервера приложение показывает в форме. Ошибка доступа (401) возвращает пользователя на экран входа.

# Аутентификация и доступ

- Регистрация и вход выдают два токена. Access token — JWT со сроком 30 минут. Refresh token — случайная строка со сроком 7 дней.
- БД хранит только SHA-256 хеш refresh token. Пароли хранятся в виде bcrypt-хешей.
- Защищённые маршруты API требуют заголовок `Authorization: Bearer <access token>`. Без него ответ — 401.
- При ответе 401 клиент сам запрашивает новую пару токенов по refresh token и повторяет запрос. Неудача возвращает пользователя на экран входа.
- Обновление по refresh token ротирует сессию: старый refresh token отзывается, выдаётся новая пара. Истёкший, отозванный или неизвестный refresh token даёт 401.
- Все финансовые данные принадлежат пользователю. Каждый запрос к API фильтруется по владельцу. Чужой ресурс даёт 404 и не отличается от несуществующего.
- Токены клиента хранятся в `localStorage`. Для production-версии рекомендуется переносить refresh token в httpOnly cookie.

# Структура серверного кода

Код сервера находится в папке `server/app`. Слои: `models` (ORM), `schemas` (Pydantic), `repositories` (доступ к БД), `services` (бизнес-правила), `api` (маршруты). Транзакции держит Unit of Work. Аутентификация: `core/security.py` (bcrypt, JWT), `services/auth.py`, `api/v1/auth.py`.

# Структура клиентского кода

Код находится в папке `client/frontend/src`. Слои повторяют упрощённый Feature-Sliced Design (FSD). Зависимости направлены вниз: `app → views → features → entities → shared`.

```
client/frontend/src/
├── app/                     # Настройка приложения: layout, провайдеры, стили,
│   │                          навигация; тонкие файлы маршрутов
├── views/                   # Экраны: композиция фич и сущностей, состояния данных
├── features/                # Действия пользователя: формы операции, категории,
│   │                          бюджета; экспорт отчётов
├── entities/                # Сущности: типы, CategoryBadge, BudgetProgress;
│   │                          finance — стор (Context + useReducer) и mock-API;
│   │                          user — auth-стор (сессия, вход, выход)
└── shared/                  # UI-компоненты, форматирование, валидация, конфиги;
                               api — HTTP-клиент с автообновлением токенов
```

Слой страниц назван `views`, а не `pages`. Next.js обрабатывает папку `pages` как второй маршрутизатор. Имя `views` исключает конфликт.

Данные приходят с сервера. API-слой `entities/finance/model/api.ts` ходит в FastAPI и переводит ответы в доменные модели. Стор загружает данные при входе и обновляет их ответами сервера после каждой операции.

# Запуск

1. Установите зависимости сервера: `cd server && uv sync`.
2. Создайте базу данных PostgreSQL и примените миграции:
   `uv run alembic upgrade head`.
3. Задайте настройки в `server/.env` (см. `.env.example`). Обязательно задайте свой `JWT_SECRET_KEY`.
4. Запустите сервер: `make backend-dev`. Адрес: `http://localhost:8000`. Документация API: `http://localhost:8000/docs`.
5. Установите зависимости клиента: `cd client/frontend && npm install`.
6. Запустите клиент: `make dev`. Откройте адрес `http://localhost:3000`.

Примечание: клиент ожидает сервер по адресу `http://localhost:8000`. Другой адрес задайте переменной `NEXT_PUBLIC_API_URL` при сборке клиента.

# Ограничения

Внимание: токены клиента хранятся в `localStorage`. Для production-версии перенесите refresh token в httpOnly cookie. Экспорт PDF открывает диалог печати браузера. Внешний вид PDF зависит от браузера.
