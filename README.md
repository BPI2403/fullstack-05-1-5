## Назначение
Учёт личных финансов: доход/расход, категории, вписывание в бюджет.

## Пользовательские сценарии
- CRUD транзакции    
    - C:Пользователь нажимает кнопку `Добавить операцию`, заполняет сумму, выбирает тип (доход/расход), категорию и дату, после чего транзакция появляется в списке.
    - R:Пользователь находит транзакцию в списке.
    - U:Пользователь находит транзакцию в списке и нажимает кнопку `Изменить`.
    - D:Пользователь находит транзакцию в списке и нажимает кнопку `Удалить`.
- CRUD категории
    - C:Пользователь переходит в раздел категорий, чтобы добавить новую (например: Развлечения, Фриланс) или просмотреть существующие.
    - R:Пользователь переходит в раздел категорий.
    - U:Пользователь переходит в раздел категорий и нажимает кнопку `Изменить`.
    - D:Пользователь переходит в раздел категорий и нажимает кнопку `Удалить`.
- CRUD бюджета
    - C:Пользователь задаёт лимит трат для выбранной категории на месяц (например, 20 000 ₽ на "Еду").
    - R:Пользователь видит шкалу прогресса с суммой потраченных средств и остатком бюджета.
    - U:Пользователь нажимает `Изменить` и корректирует сумму лимита.
    - D:Пользователь нажимает `Удалить`, снимая ограничение с категории.
- Экспорт отчёта
    - Пользователь переходит в раздел отчётов, выбирает временной период (месяц/квартал/год) и формат (CSV/PDF), после чего нажимает `Скачать` для сохранения файла с финансовой выгрузкой.

## Экраны
- **Главная (`/`)**

  Виджеты с остатком общего баланса, суммами доходов и расходов за текущий месяц, прогресс-барами активных бюджетов и лентой последних транзакций.

- **Транзакции (`/transactions`)**

  Полный список всех операций с возможностью поиска, фильтрации по датам/категориям, а также кнопками создания, редактирования и удаления транзакции.

- **Категории (`/categories`)**

  Управление категориями доходов и расходов: просмотр списка, добавление новых категорий и редактирование существующей структуры.

- **Бюджеты (`/budgets`)**

  Экран настройки и отслеживания месячных лимитов по категориям с визуальным индикатором расхода средств.

- **Отчёты и экспорт (`/reports`)**

  Графическое распределение трат по категориям, динамика доходов/расходов за выбранный период и форма экспорта данных в CSV/PDF.

## Структура frontend (упрощённый Feature-Sliced Design)

Код клиентского приложения (`client/frontend`) разделён на слои с ясным назначением; зависимости направлены строго вниз: `app → views → features → entities → shared`.

```
client/frontend/src/
├── app/                     # Настройка приложения: корневой layout, провайдеры,
│   │                          глобальные стили с анимациями, боковая навигация
│   ├── layout.tsx, providers.tsx, globals.css
│   ├── ui/navigation.tsx
│   └── page.tsx, */page.tsx # Тонкие файлы маршрутов, реэкспортирующие views
├── views/                   # Страницы-экраны: композиция фич и сущностей,
│   │                          состояния загрузки/ошибки/пустоты
│   ├── home/  transactions/  categories/  budgets/  reports/
├── features/                # Пользовательские действия
│   ├── transaction-form/    # Диалог создания/редактирования операции + схема валидации
│   ├── category-form/       # Диалог категории (+ проверка уникальности имени)
│   ├── budget-form/         # Диалог бюджета на месяц
│   └── report-export/       # Экспорт CSV (с BOM) и PDF (окно печати), периоды
├── entities/                # Сущности предметной области
│   ├── category/ transaction/ budget/   # Типы + UI (CategoryBadge, BudgetProgress)
│   └── finance/             # Общий стор: React Context + useReducer, mock-API
│                              с имитацией задержки/ошибки, селекторы (итоги, траты)
└── shared/                  # Переиспользуемые компоненты и утилиты
    ├── ui/                  # Button, Dialog, Table, Select, Skeleton, EmptyState,
    │                          ErrorState, DataBoundary, FormField, StatCard, BarChart…
    ├── lib/                 # cn, форматирование сумм/дат, клиентская валидация
    └── config/              # Пункты навигации
```

Примечание: слой страниц назван `views`, а не `pages`, потому что Next.js интерпретирует каталог `pages`/`src/pages` как Pages Router — переименование позволяет использовать App Router без конфликтов.

Данные сейчас отдаются mock-слоем (`entities/finance/model/mock-api.ts`) с задержкой и имитацией сбоя — структура повторяет будущие ответы API, так что при интеграции с бэкендом заменяется только источник данных.

## Интерактивность и состояния интерфейса

- **Формы и валидация.** Все три формы (операция, категория, бюджет) валидируются на клиенте: обязательные поля, положительная сумма с максимум 2 знаками после запятой, дата не в будущем, длина описания, уникальность имени категории. Ошибки выводятся под полями (`role="alert"`, красная рамка поля, встряска диалога при неудачной отправке).
- **Состояния данных.** Каждый экран обрабатывает три состояния через `DataBoundary`: скелетоны при загрузке, карточку ошибки с кнопкой «Повторить» и заглушку для пустых данных (с призывом к действию). Проверить ошибку можно, открыв `/` с параметром `?error=1`.
- **Управление состоянием.** Общий стор на React Context + `useReducer` хранит операции, категории и бюджеты; действия (CRUD) типизированы, изменения сразу видны на всех экранах (например, новая операция влияет на прогресс бюджетов и отчёты).
- **Анимации.** Появление страниц (`fade-in-up`), открытие/закрытие диалогов и оверлея, появление новых строк списков, рост столбцов диаграммы, плавный прогресс бюджетов, hover-подъём карточек; всё отключается при `prefers-reduced-motion`.
- **Типизация.** TypeScript strict: типы сущностей, инпутов форм, ошибок полей (`FieldErrors<T>`), правил валидации (`Validator<V>`), пунктов навигации и данных диаграмм.
